# Bounded production startup compilation

The native novel-identity matrix supports a production prototype. Eight workers reduced median native-ready time by a further 36 to 41 percent versus four on this host, with small process RSS growth. Primed differences between four and eight were below one millisecond. This supports a local cap choice; it does not establish the best cap on other machines or include compiler-service resources. The actual serial PE baseline now measures the production prewarm body, including cache persistence and compaction, before the implementation changes.

Add a core startup_work batch helper capped at min(available_parallelism, 8, item_count), counting the coordinator as one worker. Every device owns its workers, stop flag and result storage. There is no global shared scheduling state, and multiple devices may each use the cap. Simultaneous-device compiler-service/resource scaling is not measured. A failed worker creation logs and leaves all unclaimed jobs for the coordinator and already-created workers. The helper checks cancellation between admissions, finishes admitted work and returns results in input order.

Drop scoped worker handles and let thread::scope wait for its internal completion counter. Installed Rust source confirms this uses ScopeData's running-thread count and parking, rather than the Win32 thread handle join that Wine can invalidate. This preserves the existing long-lived prewarm cancellation workaround, maintained separately by issue 673. Tests cover exactly-once results, cap including the coordinator, first and partial spawn rejection, pre-cancellation, in-flight cancellation with another device progressing, and result ownership. Admission and release waits in tests use bounded failure timeouts and release-on-drop cleanup.

Keep stale MSL regeneration and cache append serial and in disk traversal order. Collect successfully refreshed shader references, compile libraries in a bounded batch, then install results on the coordinator. The full library barrier precedes pipeline dependency resolution. Deduplicate resolved pipeline keys before the bounded PSO batch, then assemble sibling mappings after all admitted PSOs finish. Cache compaction remains after all native work and before the result transfer; cancellation still skips compaction. Workers never own or append a cache writer. Shader failures omit their dependent recipes, PSO failures omit the failed handle, and retained disk records remain available for later attempts. No gameplay lookup or miss-compilation path changes.

Integrate only after issue 673 merges, preserving its sole-sender ownership and unavailable-prewarm write-disable semantics. The independent core helper is prepared now; candidate PE wiring is retained in evidence until then. Run formatting, check, isolated tests and full conformance on the final source, with the existing replay tests verifying rendered pixels and no extra cache appends for warm shader/PSO hits.

Measure the candidate on the same independent copied exact caches and semantically matched novel-identity fixtures. Retain startup elapsed, first readback, operation totals, counts, siblings and process costs separately. The clear/readback probe establishes barrier completion and cache stability, not rendered correctness of imported game shaders. If the candidate gains persist, run a small alternating saved-baseline/candidate binary block with fresh unique identities to address temporal order. No shared cache purge; novel source identity never implies a guaranteed cold driver cache. No production speed claim precedes those measurements.

## Rules check

CONTRIBUTING.md: native and actual production baseline measurements precede the change. Worktree, input copies, binary snapshots, logs and reports remain under the primary repository's ignored .codex. All install-bearing make commands use ISOLATED=1 and the pinned WINE_SDK environment. No game launch or shared SDK/cache mutation is introduced. Final fmt, check, isolated test and conformance gates must be green before the issue commit.

CONVENTIONS.md: reusable scheduling and tests live in core; PE wiring retains only native thunk orchestration. The cap is a compile-time constant, not a mutable static or runtime option. No config key, environment variable, wire field, schema change, dependency, derive, lint suppression, background queue or new unsafe block is introduced. A private spawner seam is used by production and permits injected thread-creation failures in tests. Private result structs bind each native handle to its measurements until coordinator assembly. Existing cache translation and compilation helpers are reused. New tests live in startup_work/tests.rs; stage new files before the audit.

ARCHITECTURE.md: startup remains a complete encoder barrier before frame intake. Metal handles remain device-local, worker results finish before borrowed library/source data can disappear, and device cancellation waits for every admitted native call before shutdown cleanup. Sum-of-operation measurements remain distinct from elapsed startup time. API/encoder/submit overlap and presentation are unchanged.

STATUS.md, CONFORMANCE.md and COVERAGE.md: no new D3D behavior or conformance classification is claimed. Existing pipeline replay tests cover healthy warm-hit rendering; the new core tests cover scheduling/failure/cancellation. Any additional end-to-end coverage will be recorded in the existing shaders row. The separate spawn-failure issue remains its own commit/dependency.
